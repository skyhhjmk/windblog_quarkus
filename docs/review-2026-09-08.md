## Findings addressed

- **P1:** The local MCP endpoint had no Bearer token. The launcher now creates a persistent token under the ignored test-data directory and passes it through Compose.
- **P1:** Commons inspection was unavailable because migration 011 granted only `media.search`. Additive migration 012 grants `media.inspect` and `media.import`; import now checks its own permission. Migration 011 is preserved for databases where it has already run.
- **P1:** Optional images also disabled task-bound URL validation. Image-free drafts remain valid, but every included image must match the current task's upload evidence.
- **P2:** Draft request identity omitted practical verification and server selection. Verification requests now include a normalized server set in both the request key and outgoing payload.
- **P2:** SSH waited for exit before draining stdout, allowing commands with large output to block until timeout. Output is drained concurrently while retaining a bounded prefix.
- **P1:** Live Commons search could not connect although container curl succeeded through the configured proxy. The Java client now uses the configured HTTPS proxy, with an explicit Wikimedia proxy override.
- **P2:** Commons downloads allocated the full body before checking the size. Reads now stop at the limit plus one byte. Ordinary I/O failures no longer interrupt the worker thread.
- **P2:** Image review tracked only a title and time. Import now also checks the reviewed bytes and metadata; expired reviews are evicted and the pending-review count is bounded.
- **P2:** Commons raster thumbnails could retain an SVG/TIFF filename and fail upload validation. The extension now follows the downloaded MIME type.
- The JSONL fixture now waits for asynchronous notifications before asserting their count, eliminating a response/notification race in the test.
- Flutter analyzer findings were fixed; cancelling campaign authorization now disposes its text controllers.

The existing daily/high-risk authorization changes and Commons evidence fields are included in the submodule-first delivery. Daily publication keeps idempotency headers; sensitive settings, server credentials and bulk email campaigns retain step-up authorization.
